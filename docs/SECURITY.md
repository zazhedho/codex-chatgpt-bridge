# Security

## Trust boundaries

MCP is an authenticated remote-facing control surface, even while the bridge currently binds only to loopback. The bearer token authorizes one local principal across all approved workspaces. It is not per-person identity. Local workspace approval is separate from MCP authentication.

Codex receives task text and can read source inside an approved workspace. Treat repository files, tool output, model responses, and task results as untrusted. Instructions in a repository cannot change bridge authorization or sandbox configuration.

## Enforced controls

- **Network listener:** numeric loopback only. Authentication mode is exclusive: default/local `bearer` requires a 32-byte token compared in constant time; optional `cloudflare_access` accepts only a verified `Cf-Access-Jwt-Assertion` and has no bearer fallback. Cloudflare assertions are checked against HTTPS issuer, Access app audience, exp/nbf, RS256 JWKS, and an exact email allowlist. MCP and health routes share the selected mode. Go MCP SDK localhost protection and Go cross-origin protection remain enabled.
- **Workspace:** explicit registration and local approval; absolute canonical paths, symlink checks, stable device/inode checks, and revalidation on each workspace lookup. Trusted roots are also local-only grants. A root-derived logical workspace is scoped to the nearest `.git` boundary, defaults read-only, and is bound to its approved root identity. Tasks, threads, and results are bound to one workspace and selected thread.
- **Codex profile:** read-only is the default. A workspace must be explicitly write-enabled through local `bridge-admin`, and every write task needs a separate expiring, single-use local approval. The fixed App Server profile denies filesystem root access, allows runtime-minimal reads, and scopes writes to the one approved workspace root. Sensitive paths are denied; `.git`, `.codex`, `/tmp`, and `$TMPDIR` cannot be written; command networking, Codex MCP servers, and web search are disabled. Only the resolved Codex executable gets a narrow read grant so the local macOS sandbox helper can start. The bridge checks App Server's effective profile, runtime root, extra writable roots, temp exclusions, and network state before each new or resumed turn. Unsupported or missing profile support fails closed. No caller-supplied sandbox settings are accepted.
- **App Server surface:** the adapter allows only fixed thread/turn operations plus `thread/list` and metadata-only `thread/read`. MCP cannot call raw RPC, `command/exec`, `process/spawn`, or shell tools. `codex_list_local_sessions` uses `thread/list` with CLI source filters, state-database-only metadata, bounded pagination, recent-activity sorting, and `archived:false`; archived threads are not listed, and Bridge has no unarchive operation. It is denied until the owner grants catalog access locally. After that explicit grant, the catalog returns `thread.name` or a secret-redacted, single-line preview capped at 160 characters as `displayName`; it never reads or returns turns or raw conversation history. Absolute paths remain hidden. `thread/read` uses `includeTurns:false`. Server-initiated approval requests are declined.
- **Session grants:** global catalog access and per-workspace session trust are persistent SQLite settings, both default off, audited, and revocable only through local `bridge-admin`. Workspace trust remains bound to its approved canonical path/device/inode. It allows selecting CLI sessions without per-session attach approval but never enables workspace write. Untrusted workspaces retain the separate attach approval.
- **Persistence:** Go uses a separate SQLite directory, mode-restricted files, explicit migrations, prepared SQL, foreign keys, transactions, and busy timeout. Prompts are stored only as SHA-256; task outputs remain plaintext locally and expire 30 days after task update by default.
- **Operations:** bounded prompt/body/output/progress sizes; each MCP tool result is capped at 1 MiB, request bodies at 64 KiB, prompts at 20 KiB, task output/diffs at 64 KiB, and progress at 100 bounded events; one active worker and a queue of 20; task cancellation and shutdown propagation; restart marks active work interrupted and never replays it.
- **Approvals:** remote callers may request workspace registration and write-task approval; they cannot approve either. Write task and approval are inserted atomically. Approval binds task ID, workspace, thread, mode, and exact prompt hash; the worker verifies the binding, consumes once, and clears the pending prompt in the same transaction that queues the task. Expiry, rejection, cancellation, write-disable, and consumption clear the stored prompt. Approval expires after five minutes by default. No privileged executor is connected.

The local sandbox gate passed on Codex App Server `0.163.0`: new-thread, same-process resume, and post-restart resume each ran a syscall probe under the effective read-only policy. The probe read its approved fixture and received OS `EPERM` for sibling reads and workspace writes; fixture hashes stayed unchanged. A deterministic local provider stub supplied the tool call, so this proves the App Server/bridge/sandbox execution path, not real-model tool-selection behavior.

## Limits and residual risk

- The sandbox is enforced by Codex/macOS permission profiles. The E2E proves the tested runtime and probes, not that every future Codex/macOS version or kernel path is free of bypasses. App Server is experimental. Re-run the E2E after Codex updates before trusting task execution.
- `/mcp` (including MCP initialize, tools discovery, and invocation) and `/healthz` are protected by the selected auth mode. In Cloudflare mode the tunnel must set its origin `httpHostHeader` to the exact loopback origin (`127.0.0.1:8787` by default); this preserves the MCP SDK's DNS-rebinding check. The bridge separately verifies the signed Access assertion and pins that Host. It does not trust `Authorization`, `X-Forwarded-Host`, or other identity headers. Cloudflare Managed OAuth discovery is served at Cloudflare's edge; the bridge does not implement an OAuth server. Local tests cover the handler path with a synthetic verifier and independently test real JWT/JWKS validation.
- `:minimal` exposes runtime paths needed by tools outside the project. The profile denies other filesystem roots, but source and tool output inside the registered project remain readable and may contain sensitive code.
- The Codex process needs its local sign-in to contact OpenAI. This is separate from sandboxed subprocess network policy; prompts and readable source are sent to the configured Codex service. The bridge does not pass unrelated environment secrets to the child process.
- Read-only filesystem permissions do not prevent confidentiality loss through model context or an App Server/runtime vulnerability. Never register production secrets or credential-heavy directories unless that exposure is acceptable.
- Secret redaction is heuristic and not a security boundary. Do not put credentials in prompts. MCP output, SQLite results, progress, diffs, and approval parameters may contain project information.
- A pending write prompt is stored as plaintext in the local SQLite approval row so the worker can execute it after approval. It is cleared when the approval is consumed, rejected, cancelled, expired, or the workspace write mode is disabled. Protect `BRIDGE_DATA_DIR` while approvals are pending.
- SQLite is plaintext. Protect and back up `BRIDGE_DATA_DIR` accordingly. Expiry removes task output but preserves task metadata and audit rows.
- Anyone with the bearer token can access every approved workspace while the bridge is available. Keep the listener on loopback and the token local.
- The older OpenAI Secure MCP Tunnel runbook describes a static bearer profile. The Cloudflare path is separate: it uses Managed OAuth at Cloudflare and a JWT assertion at the local origin, with no static bridge-token fallback. Read-only ChatGPT calls through the configured Cloudflare route were previously verified; this new write tool still needs ChatGPT tool refresh and an end-to-end write check.
- Workspace write can be enabled per workspace, but remains off by default and still requires local approval per task. No production operation, cloud action, privileged runner, launchd service, or public listener is enabled by this feature.
- An App Server's thread status is not a reliable cross-process lock for another Terminal Codex CLI. Close that CLI session before requesting attach; Bridge rejects sessions reported active by its App Server but cannot prove another process has stopped writing the rollout. A local attach approval binds identity and current session metadata, not a global process lock.
- Global catalog approval reveals local session IDs, project labels, activity timestamps, and status metadata for sessions in explicitly approved workspaces or active trusted roots. Sessions outside those permissions are omitted. Root-derived workspaces start read-only; trusted-root approval does not grant write. A separate local workspace write opt-in and per-task approval remain required. `canResume` is advisory if a different Terminal process is not visible as active; App Server rejects an active-writer resume, and Bridge never takes over that process.
- App Server 0.163.0 reported the real Codex TUI fixture as `source=vscode`, `originator=codex-tui`; upstream also documents that the umbrella App Server can label sessions as `vscode` regardless of host. The exact originator allowlist excludes ordinary editor-originated sessions, but originator is local metadata, not a cryptographic process identity. Local approval and current sandbox checks remain required. See the [upstream source classification issue](https://github.com/openai/codex/issues/23442).

## Workspace rules

Register the smallest project root required. Do not register `$HOME`, `~/.ssh`, `~/.aws`, `~/.kube`, Codex home, or production credential stores. The Codex profile denies known sensitive paths inside a workspace, including environment files, keys, credentials, Terraform state, `.ssh`, `.aws`, `.kube`, and selected Git credential/config paths. These rules are defense in depth, not a reason to store secrets in a project root.

Trusted roots grant session metadata discovery and read-only resume beneath the selected parent. They are not MCP-manageable, never trusted on startup, and can be disabled or revoked locally. Project boundaries use the nearest in-root `.git` marker; symlink escapes and unresolved boundaries do not receive automatic root-based access. Root revocation blocks future discovery and queued task execution, but does not interrupt a task that already started. See [Trusted Workspace Roots](trusted-workspace-roots.md) for setup and lifecycle commands.

## Safe operating steps

1. Keep `BRIDGE_HOST` at `127.0.0.1`; never port-forward or reverse-proxy the listener publicly.
2. Keep `BRIDGE_AUTH_TOKEN` in a local shell or secure local store. Do not pass it in prompts, MCP responses, screenshots, command-line arguments, or source control.
3. Approve workspace requests locally after checking canonical path and contents.
4. Start with a disposable workspace and inspect task results before sharing them.
5. Review output retention and SQLite access before using confidential repositories.
6. Keep Secure MCP Tunnel and ChatGPT connector inactive until their account permissions and header forwarding are validated.

See [approval model](APPROVAL_MODEL.md) for why natural-language confirmation cannot authorize privileged execution.
